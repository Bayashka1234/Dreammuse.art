# Dream the Muse — карманный оракул в Telegram

Первая версия для **@DreamTheMuseDeploy1052_bot**: готовые ответы без ИИ,
OpenRouter и дополнительных зависимостей. Код не запускает бота автоматически.

## Что умеет

- `/start`, `/menu`, `/help` — приветствие и кнопки.
- `/oracle` — развлекательное послание из 10 заготовок. Выбор стабилен для
  конкретного чата в течение дня по UTC; в разные дни возможны повторы.
- `/music`, `/art` — ссылка на сайт автора https://dreammuse.art.
  Отдельные треки и работы пока не добавлены: бот не выдумывает их названия и ссылки.
- `/about` — описание проекта, `/privacy` — обработка данных.
- Свободный текст показывает подсказку, медиа — просьбу использовать текст.
- Только личные чаты: группы, каналы, сообщения ботов и правки игнорируются.

Переписка не записывается в базу и не отправляется ИИ. Обработчик не логирует
сообщения и секреты. Telegram и хостинг могут обрабатывать технические данные.

## Запуск владельцем

1. Слейте PR с этим кодом в основную ветку проекта **dreammuse.art**.
2. Создайте в менеджере паролей случайный секрет из 32–256 символов:
   латинские буквы, цифры, `_` и `-`. Это **новый** `TELEGRAM_WEBHOOK_SECRET`,
   не токен BotFather и не секрет приложения Vercel Web Chat.
3. В Vercel выберите проект → **Environment Variables**.
   Добавьте `TELEGRAM_WEBHOOK_SECRET`, тип **Secret**, только **Production**.
   Не добавляйте боевой webhook в Preview: тестовые ветки не должны перехватывать бота.
4. Разверните **новый код** после сохранения переменной. Дождитесь Ready.
   Скопируйте фактический стабильный production-домен из проекта и добавьте
   путь `/api/telegram`. Домен должен вести именно на этот проект и эту версию.
   Не используйте URL чужого проекта или временного preview.
5. На своём компьютере в клоне репозитория (Node.js 24) создайте локальный
   файл `.env.telegram` в текстовом редакторе. В нём укажите:
   - `TELEGRAM_BOT_TOKEN` — токен нужного бота из @BotFather;
   - `TELEGRAM_WEBHOOK_SECRET` — тот же секрет, что в Vercel;
   - `TELEGRAM_WEBHOOK_URL` — полный production HTTPS-адрес с `/api/telegram`.
   Формат каждой строки: `ИМЯ=значение`. Не отправляйте файл и его содержимое
   в чат, Git, скриншоты или логи. `.env*` исключены из Git и загрузки Vercel.
6. Из корня репозитория выполните `npm run telegram:setup`.
   Скрипт проверяет имя бота, существующий webhook и доступность обработчика
   с секретом, затем регистрирует webhook и сверяет адрес через `getWebhookInfo`.
   Токен и ответы Telegram с приватными данными не печатаются.
   Существующий другой webhook не заменяется без явного
   `TELEGRAM_REPLACE_WEBHOOK=true` в локальном файле. Это отключит старый обработчик:
   сначала убедитесь, что он больше не нужен. Не запускайте скрипт повторно вслепую,
   если регистрация могла выполниться, а проверка результата не завершилась.
7. Откройте бота в Telegram, нажмите **Start** или отправьте `/start`.
   Проверьте все четыре кнопки и свободный текст. До этого реальная доставка
   ответов остаётся непроверенной. После регистрации удалите локальный файл,
   если он больше не нужен; храните секреты в менеджере паролей.

Токен BotFather нужен только для однократной регистрации, в работающей функции
он не используется. Не требуются `OPENROUTER_API_KEY`, `OPENROUTER_MODEL`
или ключи существующего `/api/chat`.

### Защита и диагностика

- Telegram должен иметь доступ к endpoint без Vercel login. Если deployment
  protection блокирует запросы, скрипт остановится до регистрации. Не отключайте
  защиту всего проекта без отдельного решения владельца; настройте подходящий
  публичный production endpoint. Секрет webhook обязателен в любом случае.
- `503`: переменная отсутствует или не соответствует формату. После изменения
  переменных требуется новое развёртывание.
- `401`: не совпадает `TELEGRAM_WEBHOOK_SECRET`.
- `405` при открытии endpoint браузером ожидаем: разрешён только POST.
- Telegram Bot API `getWebhookInfo` показывает очередь и ошибки доставки.
  Не публикуйте его полный вывод. Скрипт не удаляет ожидающие сообщения.
- При смене секрета обновите Vercel, разверните заново и повторно зарегистрируйте
  webhook с новым секретом. Не запускайте конкурирующий `getUpdates`-polling.

Ответ отправляется методом `sendMessage` прямо в JSON-ответе на webhook.
Это не требует исходящего запроса из Vercel, но Telegram не возвращает
результат такого `sendMessage`. Нужна ручная проверка в Telegram. Нет постоянной
очереди/дедупликации: при повторной доставке update возможны повторные ответы.
Автоматических рассылок, загрузки музыки и свободного ИИ-диалога в этой версии нет.

## Проверка без настоящих ключей

Вызовите обработчик локально с подставным секретом окружения и mock req/res.
Проверьте отказ без секрета/с неверным секретом, все команды и кнопки, JSON в
объекте/строке/Buffer, игнорирование групп, стабильность послания в пределах дня,
ошибки метода/типа/размера/JSON. Регистрационный скрипт экспортирует
`configureWebhook(env, request)`, поэтому его сетевые ответы можно подменить.
