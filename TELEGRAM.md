# Dream the Muse — облачный Архитектор 1052

Проект Vercel: **dreammuse.art-api**. Репозиторий: Bayashka1234/Dreammuse.art,
ветка main. Root Directory должен быть корнем репозитория (пустое значение),
а не `api`: функция лежит в `api/telegram.js`, зависимости — в корне.
Production endpoint: `https://dreammuseart-api.vercel.app/api/telegram`.
Изменения других сайтов и графов не нужны.

## Настройка (секреты не отправлять в чат и GitHub)

Выберите проект в Vercel → **Environment Variables** в боковой панели.
Введите значения, выберите **Production**, сохраните:

- `TELEGRAM_BOT_TOKEN`: НОВЫЙ токен @DreamTheMuseDeploy1052_bot. Если старый
  публиковался, сначала отзовите его через BotFather. Не использовать старый.
- `OPENROUTER_API_KEY`: ваш действительный ключ OpenRouter (тип Secret).
- `TELEGRAM_WEBHOOK_SECRET`: случайный секрет из менеджера паролей,
  32–256 латинских букв, цифр, `_` или `-` (тип Secret).
- `TELEGRAM_OWNER_ID`: числовой ID вашего личного аккаунта, не ID бота.
- `OPENROUTER_MODEL`: необязательно; по умолчанию `openrouter/free`.
  Доступность, лимиты и стоимость модели зависят от OpenRouter.

Telegram-токен тоже сохраняйте как Secret. Боевые ключи не нужны в Preview.
После добавления переменных нужен НОВЫЙ deployment: старый их не получит.
GET `/api/telegram`: HTTP 503, если конфигурация отсутствует/неверного формата;
HTTP 200 и `configured: true`, если формат прошёл проверку. Это ещё НЕ проверка
ключей, модели, доставки Telegram или статуса webhook.

## Подключение Telegram

Существующий `scripts/setup-telegram.js` запускается только владельцем локально
через `npm run telegram:setup` (Node.js 24, `.env.telegram`). Туда локально
нужно записать те же TELEGRAM_BOT_TOKEN, TELEGRAM_WEBHOOK_SECRET и
`TELEGRAM_WEBHOOK_URL=https://dreammuseart-api.vercel.app/api/telegram`.
Секреты в аргументы команд не вставлять. Скрипт проверяет getMe, существующий
webhook и production endpoint перед изменением доставки. Если другой webhook
уже зарегистрирован, заменять его только осознанно с TELEGRAM_REPLACE_WEBHOOK=true.
Не удалять ожидающие обновления. Не регистрировать webhook при GET и в preview.
После проверки webhook остановить локальный polling, если он ещё работает.

Telegram должен иметь доступ к production endpoint без входа в Vercel.
Не отключайте защиту вслепую: сначала проверьте HTTP и технические логи.

## Возможности и ограничения

- Личные сообщения только от TELEGRAM_OWNER_ID, проверяются from.id и chat.id.
- /start, /menu, /help, /privacy, /reset и Вектор — готовые ответы.
- Тексты, музыка, визуальные идеи, Оракул и ритуалы — OpenRouter через fetch.
- Гадания — художественная игра; ритуалы — безопасные творческие упражнения.
- Кнопка Портал ведёт на существующий GitHub Pages сайт.
- Нет постоянной памяти, доступа к компьютеру, генерации изображений или аудио.
  Не обещать эти функции. Сообщения отправляются OpenRouter/поставщику модели.

POST проверяет секрет и Update, затем быстро отвечает HTTP 200. Генерация и
sendMessage продолжаются с `waitUntil` из @vercel/functions. У функции лимит
120 секунд; запрос ИИ — 45 секунд; отправка — до трёх частей по 3000 символов,
с тайм-аутом 15 секунд на часть. Логи содержат только безопасные коды ошибок.
`waitUntil` не является надёжной очередью: нет долговечных повторов, истории,
защиты от повторной доставки update_id и гарантии exactly-once. HTTP 200 не
доказывает доставку. Для следующих этапов нужна отдельная очередь/база.

## Проверка

`npm ci` и `node scripts/check-telegram.js` — изолированная проверка с mock API,
без реальных ключей и расходов. После production deployment отправить /start,
проверить меню и обычное сообщение с каноном 387 → 1052 → ∞. Только ответ в
Telegram подтверждает доставку. Секреты/тело переписки в отчёты не включать.
